# 邮件发送

三种 Agent 模式均支持 `send_email`，Multi-Agent 通过 EMAIL 角色执行。工作台示例：`给 user@example.com 发一封邮件，主题是会议通知，正文是明天上午十点开会。`

管理员配置以下环境变量并重启后端：

```text
MAIL_ENABLED=true
MAIL_HOST=smtp.example.com
MAIL_PORT=587
MAIL_USERNAME=agent@example.com
MAIL_PASSWORD=邮箱SMTP授权码
MAIL_FROM=agent@example.com
MAIL_AUTH=true
MAIL_SSL=false
MAIL_STARTTLS=true
```

当前 `application.yml` 中 `MAIL_ENABLED` 默认值为 `true`；不使用邮件发送时可设置 `MAIL_ENABLED=false`。启动时不会主动连接 SMTP，实际发送需要有效配置。587 端口默认要求 STARTTLS；使用 465 隐式 TLS 时设置 `MAIL_PORT=465`、`MAIL_SSL=true`、`MAIL_STARTTLS=false`。凭证放在环境变量或被 Git 忽略的 application-local.yml 中，不提交到仓库。

参数为 `to`、`subject`、`body`，仅支持单个邮箱、最多200字符的主题和最多64 KiB UTF-8纯文本正文。发件人固定为管理员配置，不支持附件、HTML、抄送或密送。SMTP连接超时10秒，读写超时15秒。

沿用模型判断的人工审批流程；需要先确认时明确要求“发送前先让我确认”，使用工作台任务入口批准冻结的完整发送参数。该工具本身不强制审批。发送按顺序执行，不自动重试。成功仅代表SMTP服务器接受，不保证最终投递；异常或任务超时后可能已经发送，应核查邮件服务记录再决定是否重试。
