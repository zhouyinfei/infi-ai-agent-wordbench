# AI Agent 平台需求文档

版本：V0.5（已实现用户系统，新增 ReAct 同步执行）  
日期：2026-10-10  
状态：用户已授权分阶段开发；已实现用户系统，本轮仅实现 ReAct 同步执行，其他能力按阶段推进。

## 1. 项目定位

建设一个支持对话、知识检索、工具调用与任务协作的通用 AI Agent 平台。用户通过自然语言提出目标，系统根据任务类型选择执行策略，调用知识库、联网工具及外部服务；在敏感操作前交由人工审批，并持续展示执行进度和结果。

本项目首先以单组织、内部使用为默认范围，预留后续扩展空间。具体业务领域尚未确定，本文采用“资料检索与报告生成”“多步骤业务任务”作为验证场景。这是需求假设，需在评审时确认。

### 1.1 建设目标

- 支持 ReAct 与 Plan-and-Execute 两种执行策略。
- 通过 MCP 接入外部工具和资源，统一管理调用权限。
- 支持会话记忆、长期记忆与 RAG 知识检索。
- 支持受控的 Multi-Agent 协作和结果汇总。
- 支持 Human-in-the-Loop、人工输入与审批流。
- 支持异步任务、并行工具调用、取消与失败恢复。
- 支持多模型适配、运行时切换和联网检索。
- 提供可追踪、可审计、可验收的任务执行过程。

### 1.2 范围边界

初始版本提供通用平台与示例场景，不承诺自动理解任何业务系统，也不默认允许 Agent 无人监管地执行具有外部影响的操作。工具的业务功能、权限和风险级别须显式配置。

暂不纳入首期范围：模型训练或微调、语音视频交互、复杂可视化工作流设计器、多组织商业化计费、跨地域部署，以及任意代码或终端命令执行。是否需要这些能力，在后续评审中单独决定。

## 2. 用户角色与权限

| 角色 | 核心权限 |
| --- | --- |
| 普通用户 | 创建会话、提交任务、查看自身任务、提供补充信息、取消任务、使用授权知识库和工具 |
| 审批人 | 查看分配给自己的审批事项、批准或拒绝、填写意见 |
| 管理员 | 管理模型、Agent、MCP 服务、工具权限、知识库、审批策略和系统配置 |
| 审计人员 | 按授权查看任务记录、工具调用和审批日志，不修改执行结果 |

允许同一用户拥有多个角色。所有任务、记忆、知识库、工具和审批记录必须进行服务端权限校验。普通用户默认只能访问自身数据；共享范围需要显式授权。

## 3. 核心使用场景

### 3.1 知识问答

用户选择知识库并提问，系统检索相关片段，组织答案并附来源。资料不足时说明证据不足，可在用户授权的联网范围内补充检索。

### 3.2 联网研究与报告

用户提交研究目标，系统生成计划，并行查询互不依赖的信息源，读取网页、整理证据、生成报告。用户可查看引用来源、查询时间及执行进度。

### 3.3 多步骤业务任务

用户提交包含查询和写入的目标。Agent 先查询必要信息，再形成待执行操作。涉及发送、删除、修改或其他配置为敏感的操作时，展示具体目标和参数，审批通过后才执行。

### 3.4 多 Agent 协作

协调 Agent 将目标拆分给研究、分析或校验等专职 Agent。独立子任务并行执行，有依赖的任务按顺序执行；协调 Agent 汇总成果，并处理冲突和部分失败。

### 3.5 中断与恢复

长任务提交后返回任务标识，用户可离开页面再回来查看。任务等待审批、等待补充输入或执行失败时保留进度，在条件满足后从允许恢复的位置继续。

## 4. 功能需求

优先级定义：P0 为首期必需，P1 为后续完整版本必需，P2 为可选增强。首期先完成可靠的执行闭环，不要求所有高级能力同时上线。

### 4.1 会话与任务管理

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| F-01 | P0 | 创建、查看、重命名和归档会话，保存历史消息 |
| F-02 | P0 | 从会话提交任务，记录目标、执行策略、模型、授权工具和知识库 |
| F-03 | P0 | 展示任务状态、步骤进度、工具摘要、审批节点和最终结果 |
| F-04 | P0 | 支持任务列表、详情、取消及失败原因查询 |
| F-05 | P0 | 对话输出与任务进度支持流式更新，断开连接不导致后台任务自动取消 |
| F-06 | P1 | 支持任务结果导出，导出格式待确认 |

一次会话允许包含多个任务。消息与任务执行记录分别保存，避免将长任务状态仅依附在对话文本中。显示可解释的执行摘要，不要求存储或展示模型内部思维链。

### 4.2 ReAct 执行策略

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| F-07 | P0 | 支持“判断下一步—调用工具—观察结果—继续或结束”的迭代执行 |
| F-08 | P0 | 工具调用前验证工具权限、参数、风险和预算 |
| F-09 | P0 | 设置最大迭代次数、任务时限和调用预算，达到限制后停止并说明原因 |
| F-10 | P0 | 工具失败时支持有限重试、替代工具或返回明确失败结果 |

工具响应是待分析数据，不能直接改变系统权限、审批规则或执行配置。重复调用无进展时应终止循环或请求用户补充信息。

### 4.3 Plan-and-Execute 执行策略

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| F-11 | P1 | 将目标拆解为带标识、依赖关系、预期输出的计划步骤 |
| F-12 | P1 | 支持执行前展示计划；是否必须确认计划由任务策略决定 |
| F-13 | P1 | 根据步骤依赖执行，允许独立步骤并行 |
| F-14 | P1 | 执行反馈导致计划调整时保留计划版本与调整原因 |
| F-15 | P1 | 限制重新规划次数，并在关键目标、操作范围变化时重新请求确认或审批 |

用户可指定策略，系统也可按配置选择策略。首期采用显式选择；自动策略路由为 P2。计划中的步骤可以使用 ReAct 完成局部执行，但仍受统一的权限和预算约束。

### 4.4 MCP 与工具管理

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| F-16 | P0 | 配置 MCP 服务地址、连接方式、认证信息、超时和启停状态 |
| F-17 | P0 | 发现工具及参数结构，支持刷新、健康检查和调用测试 |
| F-18 | P0 | 按用户、角色、Agent 和任务限制可用工具 |
| F-19 | P0 | 所有外部调用经过统一工具入口，执行参数校验、审批检查、超时及审计 |
| F-20 | P1 | 支持 MCP 资源和提示模板，并限制资源访问范围 |
| F-21 | P1 | 服务或工具定义发生变化时记录版本，对受影响配置提示重新校验 |

首期优先支持远程 HTTP 接入；本地进程接入作为可选扩展，是否启用及具体协议兼容版本在技术设计阶段确定。MCP 服务声明的描述或风险级别不作为唯一可信依据，管理员负责配置权限和风险分类。

工具配置需包含：名称、来源、参数约束、只读或写入属性、风险级别、是否幂等、重试条件、并行限制和审批规则。

### 4.5 会话记忆与长期记忆

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| F-22 | P0 | 保存完整会话记录，按上下文预算选择近期消息与历史摘要 |
| F-23 | P0 | 上下文压缩后保留任务目标、用户约束、关键事实和未完成事项 |
| F-24 | P1 | 保存跨会话的用户偏好及明确授权的长期事实，记录来源和更新时间 |
| F-25 | P1 | 用户可查看、修改、删除或关闭长期记忆 |
| F-26 | P1 | 支持记忆过期、冲突处理和检索过滤 |

短期上下文与长期记忆分开管理。未经授权不将密码、密钥等敏感信息写入长期记忆。用户删除记忆后，后续任务不可再检索使用；原始审计记录的保留与脱敏策略另行配置。

### 4.6 RAG 知识检索

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| F-27 | P0 | 创建知识库，上传文档，配置访问权限；首期至少支持 TXT、Markdown 和可提取文字的 PDF |
| F-28 | P0 | 异步完成解析、切分、向量生成和索引，展示各阶段状态及失败原因 |
| F-29 | P0 | 按知识库权限检索，返回片段、文档标识和来源位置 |
| F-30 | P0 | 回答附引用，无法检索到充分证据时明确说明 |
| F-31 | P1 | 支持关键词与向量混合检索，以及可配置的结果重排 |
| F-32 | P1 | 支持文档更新、删除、重新索引和版本追踪 |

扫描 PDF 的 OCR、Word、网页批量导入为 P2。文档删除后立即阻止检索使用，再异步清理索引。Embedding 模型变更需创建兼容的新索引或重建索引，不能直接混用不兼容的向量。

向量检索存储尚未确定。MySQL 保存文档与索引元数据，Redis 用于缓存和运行状态；是否增加独立向量数据库，在评审数据规模和检索效果后决定，不预设 MySQL 或 Redis 具备所需向量检索能力。

### 4.7 Multi-Agent 协作

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| F-33 | P1 | 配置 Agent 的角色、目标、模型、工具、知识库和执行预算 |
| F-34 | P1 | 由协调 Agent 分配子任务，记录父子任务关系和依赖 |
| F-35 | P1 | 支持独立子任务并行，统一汇总结构化结果与证据 |
| F-36 | P1 | 支持子任务失败、超时、取消及有限重分配 |
| F-37 | P1 | 限制协作深度、Agent 数量和总预算，防止递归扩散 |

首个协作模式采用“协调者—执行者”，不要求实现任意 Agent 网络。子 Agent 的权限不超过父任务授权范围，共享上下文仅包含完成子任务所需信息。对冲突结果，汇总结果需标明分歧及证据，不静默掩盖。

### 4.8 Human-in-the-Loop 与审批流

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| F-38 | P0 | 缺少关键信息时暂停任务，提出具体问题并接收用户补充 |
| F-39 | P0 | 根据工具、操作、参数范围和风险级别触发审批 |
| F-40 | P0 | 审批页展示目标对象、实际参数、预期影响、发起人和有效期 |
| F-41 | P0 | 支持批准、拒绝、过期和取消，并保存审批意见与时间 |
| F-42 | P0 | 批准仅对对应任务、工具及参数版本有效，参数变化后重新审批 |
| F-43 | P1 | 支持顺序多级审批、指定审批人及审批通知 |

首期为单级审批。高风险操作可配置禁止发起人自批。拒绝或过期后不得执行对应操作；默认结束当前执行，用户可修改目标后发起新执行。外部消息通知渠道待确认，首期提供站内待办。

审批和执行之间需防止重复批准、重复执行和条件变化。批准后执行前重新校验权限、参数版本和必要业务条件；外部状态变化影响审批结论时重新审批。已发送的邮件、已提交的外部写入等不保证可撤销，结果中需如实说明。

### 4.9 异步执行与并行工具调用

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| F-44 | P0 | 任务异步提交，立即返回任务标识，支持查询和流式事件订阅 |
| F-45 | P0 | 为无依赖且允许并发的工具调用提供有界并行执行 |
| F-46 | P0 | 配置全局、用户、任务、模型和工具的并发与速率限制 |
| F-47 | P0 | 支持单次调用超时、任务总时限和取消请求 |
| F-48 | P1 | 进程重启后从持久化检查点恢复可恢复任务 |
| F-49 | P1 | 支持退避重试和异常任务人工处理 |

存在依赖、同一资源写入或服务不允许并发时按顺序执行。取消后停止新调用，尝试中止正在执行的调用；不能中止的外部操作记录实际结果，不宣称已回滚。非幂等写入禁止无条件重试，结果未知时进入人工核对状态。

### 4.10 多模型适配与运行时切换

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| F-50 | P0 | 统一配置模型提供方、地址、模型标识、认证信息和能力标签 |
| F-51 | P0 | 统一对话、流式输出、工具调用和用量记录接口 |
| F-52 | P0 | 用户或管理员可选择模型，至少验证两个模型配置的适配能力 |
| F-53 | P1 | 运行中的任务可在步骤边界切换模型，保留执行状态和切换记录 |
| F-54 | P1 | 按配置在模型超时、限流或不可用时回退，受用户授权和能力兼容性限制 |

不在一次进行中的模型请求中强行切换。切换后重新构造上下文，校验工具调用、结构化输出和上下文长度等能力；能力不足时拒绝切换或走明确的降级策略。跨提供方回退须符合数据发送权限，不能因故障把数据发给未授权服务。

记录 Token 用量；费用仅在配置价格且用量可获取时估算，并标注估算属性。供应商和具体模型清单由用户确认。

### 4.11 联网能力

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| F-55 | P0 | 支持搜索查询和公开网页正文抓取，保存来源 URL、标题及抓取时间 |
| F-56 | P0 | 联网结果参与回答时提供引用，抓取失败或内容不足时明确说明 |
| F-57 | P0 | 按工具策略限制域名、下载大小、超时、重定向和内容类型 |
| F-58 | P0 | 防止访问本机、内网、云元数据等未授权地址，并校验重定向目标 |
| F-59 | P1 | 支持联网结果短期缓存，允许用户要求重新获取 |

联网能力以工具形式接入统一权限和审计体系。网页内容与知识库文档均视为外部数据，不得绕过审批或诱导泄露凭证。首期不要求登录网站、复杂浏览器自动化或绕过网站访问限制。

## 5. 完整执行流程与状态

### 5.1 标准流程

1. 用户提交目标，选择或采用默认 Agent、策略、模型、工具和知识库。
2. 系统校验权限、输入、并发额度和预算，创建持久化任务。
3. 加载授权记忆，按需检索知识库，构造受上下文预算限制的输入。
4. 根据策略生成下一步动作或任务计划。
5. 工具调用前检查参数、权限、审批及并发条件。
6. 缺少输入或需要审批时保存进度并进入等待状态。
7. 执行工具或子任务，记录结果、来源、用量与异常。
8. 达到目标后输出结果与引用；发生不可恢复错误或超过预算时说明已完成内容和未完成原因。

### 5.2 状态定义

| 状态 | 含义 |
| --- | --- |
| QUEUED | 已提交，等待执行资源 |
| RUNNING | 正在规划、调用模型或执行工具 |
| WAITING_INPUT | 等待用户补充必要信息 |
| WAITING_APPROVAL | 等待人工审批 |
| CANCELLING | 已收到取消请求，正在停止可停止的工作 |
| NEEDS_RECONCILIATION | 外部操作结果未知，需要人工核对 |
| SUCCEEDED | 已满足任务完成条件 |
| FAILED | 不可恢复失败、审批拒绝或策略限制导致结束 |
| CANCELLED | 已停止继续执行，外部已发生的影响单独记录 |
| EXPIRED | 等待或任务时限到期 |

QUEUED 可进入 RUNNING、CANCELLED 或 EXPIRED；RUNNING 可进入等待状态、取消中或结束状态。等待状态在有效输入或批准到达后可恢复 RUNNING。终态不直接重开，“重试”创建关联的新执行记录。模型正常返回文本不等于任务成功，成功需满足步骤完成条件。

## 8. 技术约束与设计边界

- 前端采用 HTML、JavaScript 和 Vue，负责会话工作台、任务进度、审批及管理页面，通过后端接口获取数据和接收任务进度事件。
- 后端采用 Spring Boot，运行环境为 JDK 17。具体框架版本和依赖在技术设计时确认。
- 前后端分离，前端通过后端 API 交互；后端采用 LangChain4j 作为后续 Agent 能力基础，MyBatis 负责数据访问。
- 后端严格按 controller、service、service.impl、mapper 等分层，使用独立 DTO、VO 和 DO，并遵守阿里 Java 编码规范。
- Spring Boot 通用配置与隐私配置占位备份放在 application.yml，本地隐私配置放在 application-local.yml；备份采用环境变量占位，不提交真实密码或密钥。
- MySQL 保存业务数据、任务状态、审批、配置、会话和审计等持久化记录。
- Redis 用于缓存、限流、临时执行状态及必要的协调；MySQL 中的持久化状态作为任务恢复依据。
- 异步执行可先采用数据库任务记录配合工作线程或队列机制。是否引入独立消息中间件，在容量与可靠性需求明确后决定。
- JDK 17 的首期并行方案采用有界执行资源；本文不预设升级 JDK 才能实现的特性。
- 模型适配、执行策略、工具接入、记忆、检索和审批需要具备清晰模块边界，首期可在单体应用中实现。
- 文档原文件需要持久化文件存储；首期可采用受控本地存储，生产是否使用对象存储待确认。

以上是技术约束和候选职责划分，不是最终架构、数据库表设计或代码实现方案。

## 9. 非功能需求

### 9.1 安全与审计

所有接口进行身份和权限校验，知识检索先按权限过滤。敏感操作必须按策略审批；任务恢复、模型切换和子 Agent 执行不得绕过审批。密钥加密保存或通过受控密钥配置提供，日志进行脱敏。上传文件受大小、类型和解析资源限制。

记录任务、工具调用、审批和配置变更的关联追踪标识。外部内容中的指令不能提高权限。数据保留期限、日志内容范围、备份与删除机制在上线前明确。

### 9.2 可靠性

任务状态与关键执行结果持久化。首期故障后能识别未完成任务并给出失败或待核对状态；P1 支持从检查点恢复。并发工作者不得重复领取同一有效任务，审批批准后的操作不得重复提交。外部服务无法提供幂等保障时，不承诺端到端“恰好一次”。

### 9.3 性能与容量（暂定验收基线）

以下为初始目标，需结合部署资源和测试负载评审确认：

- 在 20 个活跃用户、10 个同时运行任务的基准负载下，任务提交和状态查询接口 P95 不超过 1 秒，不含外部模型及工具等待时间。
- 每个任务默认最多 4 个并行工具调用，管理员可调整；超出并发限制时排队或返回明确限流结果。
- 进度事件正常情况下在产生后 2 秒内可在界面看到。
- 首期单文档上传上限暂定 20 MB，单知识库验证规模暂定 1,000 份文档；解析吞吐和检索响应目标在样本测试后补充。
- 模型生成、网页访问和外部工具耗时单独统计，不以固定整任务响应时长验收。

### 9.4 可观测性与维护

可查询任务成功率、失败率、排队时间、调用耗时、模型用量、审批等待时间和并发使用情况。错误区分模型、工具、检索、权限和系统异常。配置修改有审计记录；备份恢复方案与上线部署规范在技术设计阶段补充。

## 10. 分阶段交付

| 阶段 | 范围 | 完成条件 |
| --- | --- | --- |
| 第一阶段：基础闭环 | 身份权限、会话、ReAct、MCP 工具、基础 RAG、短期记忆、联网、异步与有限并行、单级审批、两个模型配置、任务审计 | 可完成知识问答、联网研究和含审批的工具任务；通过全部 P0 验收 |
| 第二阶段：协作与恢复 | Plan-and-Execute、多 Agent、长期记忆、步骤边界模型切换、故障回退、检查点恢复、多级审批、混合检索 | 可完成有依赖的协作任务，具备中断恢复和权限一致性 |
| 第三阶段：增强 | 自动策略路由、OCR、更多文件格式、可视化流程、更多集成与容量优化 | 依据实际使用反馈另行确定 |

最终完整项目包含第一、第二阶段能力；阶段划分仅用于控制实施顺序。第二阶段不是默认取消的范围。

## 11. 验收标准

采用固定样例、模拟失败工具和可控测试数据验收。模型回答质量存在波动，硬性流程、权限和状态约束必须确定性验证。

| 编号 | 范围 | 验收场景与预期结果 |
| --- | --- | --- |
| A-01 | P0 / 会话记忆 | 同一会话连续多轮追问，能使用上下文；触发摘要后仍保留明确约束，不读取其他用户会话 |
| A-02 | P0 / ReAct | 查询任务通过至少两次工具调用完成，过程可追踪；故意制造循环时在预算内停止 |
| A-03 | P0 / MCP | 接入测试服务、发现并调用工具；未授权工具、非法参数及连接超时均给出明确处理结果 |
| A-04 | P0 / RAG | 上传测试文档后可追踪索引进度，问答能定位引用；未授权文档不进入检索结果，缺少证据时说明不足 |
| A-05 | P0 / 审批 | 敏感写入在批准前调用次数为零；批准后仅提交一次；拒绝、过期、取消和参数变化不能使用原批准执行 |
| A-06 | P0 / 异步 | 提交任务立即获得任务标识，页面关闭不终止任务，重连可查询最终状态与历史进度 |
| A-07 | P0 / 并行 | 两个独立的模拟慢工具能并发执行；存在依赖时按顺序执行；并发数不超过配置上限 |
| A-08 | P0 / 多模型 | 两个模型配置完成对话和授权工具调用，记录各自模型标识、耗时与用量可用性 |
| A-09 | P0 / 联网 | 完成搜索和网页读取并返回来源；本机、内网及不允许的重定向目标被阻止 |
| A-10 | P0 / 取消与错误 | 取消后不再发起新调用；失败明确归因；外部写入结果未知时标记待核对，不自动重复写入 |
| A-11 | P1 / 计划执行 | 生成至少三个带依赖的步骤，按依赖完成任务；重规划有版本记录且不绕过审批 |
| A-12 | P1 / 多 Agent | 两个执行 Agent 完成独立子任务并汇总；子 Agent 无法取得父任务未授权的工具或数据 |
| A-13 | P1 / 长期记忆 | 经授权的偏好跨会话生效，用户修改或删除后新任务采用最新状态 |
| A-14 | P1 / 运行时切换 | 在步骤边界切换模型并继续执行；不兼容或未授权模型切换被拒绝且有原因 |
| A-15 | P1 / 恢复 | 模拟工作进程中断，任务从允许的检查点恢复；已完成敏感操作不重复执行 |
| A-16 | P1 / 多级审批 | 顺序审批未完成时不得执行，任一节点拒绝后终止该操作 |
| A-17 | P0、P1 / 审计 | 任一工具写入可追溯至任务、用户、具体参数版本和对应审批记录，普通日志不泄露密钥 |

RAG 与任务回答质量需在明确业务场景后建立样本集，定义正确性、引用准确性和任务完成率阈值；当前不编造通用准确率承诺。

## 12. 风险、依赖与处理要求

| 风险或依赖 | 处理要求 |
| --- | --- |
| 模型输出不稳定 | 校验工具参数和结构化结果，限制重试和预算；关键写入由审批控制 |
| 外部内容提示注入 | 将检索与网页内容作为数据，工具授权及审批在模型外执行 |
| 工具副作用与重复执行 | 标注幂等性，持久化调用状态；未知结果先核对 |
| 外部服务不可用 | 超时、限流、有限重试和授权范围内的降级 |
| 长任务成本增长 | 限制步骤、并发、Token 和总时长，显示停止原因 |
| 多 Agent 上下文或权限扩散 | 最小化共享上下文，继承父任务权限上限和总预算 |
| 文档质量不佳 | 暴露解析失败和空文本状态，不将未解析文档视为可检索 |
| 模型、搜索服务与 MCP 凭证未准备 | 使用模拟服务验证流程，真实联调前提供所需配置 |

## 14. 当前 ReAct 实施范围

本轮按用户要求仅实现 ReAct：单次目标、LangChain4j 原生模型工具调用、计算器与当前时间两个只读工具、动作与观察反馈、最终回答、执行预算及已登录用户的前端工作台。采用同步调用，不持久化执行记录，不引入其他 Agent 功能。具体配置、接口、限制和自测见 [ReAct 使用说明](ReAct使用说明.md)。
