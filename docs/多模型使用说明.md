# 多模型与运行时切换

在 `application-local.yml` 配置模型目录；凭证通过环境变量提供。当前适配 OpenAI Chat Completions 兼容协议，可连接 OpenAI、DeepSeek、Qwen 等提供兼容接口的服务。具体模型必须支持工具调用，兼容性应以实际服务验证为准。暂不支持 Anthropic/Gemini 原生协议。

```yaml
app:
  ai:
    default-model: primary
    models:
      primary:
        enabled: true
        provider: openai-compatible
        base-url: https://api.openai.com/v1
        model-name: ${PRIMARY_MODEL}
        api-key: ${PRIMARY_API_KEY}
        request-timeout: 30s
      secondary:
        enabled: true
        provider: openai-compatible
        base-url: ${SECONDARY_BASE_URL}
        model-name: ${SECONDARY_MODEL}
        api-key: ${SECONDARY_API_KEY}
        request-timeout: 30s
```

模型目录变更需要重启后端。运行期间在工作台“模型”下拉框切换，下次发送立即生效，无需重启；同一会话可在不同轮次使用不同模型，共用会话记忆。一次任务的全部规划、工具循环及协作角色调用使用同一模型。选择只作用于当前请求，不修改其他用户的默认模型；任务结束或异常时清理选择上下文。

登录后 `GET /api/react/models` 返回模型 ID、名称、协议、可用状态及默认标记，不返回服务地址或密钥。三个 `/runs` 接口均接受可选 `modelId`，省略或空值使用 `default-model`；未知或禁用的模型不会退回其他模型，也不自动重试。旧的 `app.ai.enabled/base-url/model-name/api-key/request-timeout` 单模型配置仍可使用；不设置 `default-model` 时其作为默认连接。

`configured` 仅表示本地配置完整，不代表已联网检测服务可达性或工具调用能力。不要把真实凭证提交到 Git。

模型 ID 包含点号等特殊字符时，YAML 键必须采用带引号的方括号形式，例如 "[deepseek-v4.1-flash]":；default-model 和请求 modelId 仍填写 deepseek-v4.1-flash，不带方括号。也可使用只含字母、数字和连字符的 ID，将真实模型名称保留在 model-name 中。
